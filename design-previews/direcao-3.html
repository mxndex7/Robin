O sync com o Supabase está duplicando itens quando a conexão cai. Por quê?
Robin15:41
Buscou na memória: sync, Supabase

O reenvio da fila não tem chave de idempotência: se a conexão cai depois de o Supabase gravar, mas antes de a resposta chegar, o Robin entende que falhou e manda o mesmo item de novo.

Como corrigir

  1. Gere um request_id estável por item, antes do primeiro envio.
  2. Faça o insert com on_conflict=request_id e ignore duplicatas.
  3. Repita com espera crescente, nunca em laço apertado.
python
def enviar(item: dict, tentativas: int = 3) -> None:
    """Reenvia sem duplicar: o request_id torna o insert idempotente."""
    for tentativa in range(tentativas):
        try:
            cliente.post("/rest/v1/memories", json=item, params={"on_conflict": "request_id"}, headers={"Prefer": "resolution=ignore-duplicates"})
            return
        except httpx.TransportError:
            time.sleep(2 ** tentativa)  # espera 1s, 2s, 4s
    raise SemConexao(item["request_id"])
